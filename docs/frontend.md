# Frontend specification

## Technology and organization

Use React with JavaScript, Vite, React Router, `socket.io-client`, native `fetch`, and plain CSS/CSS modules. Deploy the static build to Vercel. These supporting choices are explained in [tech stack](tech-stack.md).

Planned modules: `pages/`, `components/`, `features/auth/`, `features/rooms/`, `features/editor/`, `features/history/`, `services/api.js`, `services/socket.js`, and `styles/` under `client/src/`.

## Routes and screens

| Route | Content and behavior |
| --- | --- |
| `/` | Redirect to dashboard if signed in, otherwise login. |
| `/register` | Name, email, password, validation, submission status. |
| `/login` | Email/password form and generic authentication errors. |
| `/dashboard` | Member rooms, create-room form, join-by-code form, empty/loading/error states. |
| `/rooms/:roomId` | Room title, member presence, editor, save/connection status, history drawer; owner invite controls. |
| Unknown route | Accessible not-found screen with dashboard link. |

The history drawer lists revision, author, server timestamp, and type. Selecting a version shows a read-only preview. Only the owner sees restore controls, but the server remains authoritative. Confirm restore with its version number and the warning that it replaces the current note.

## Editor model

Use a plain-text textarea for the core, not a rich-text dependency. Keep three separate values: canonical server content/revision, editable local draft, and any in-flight operation snapshot.

Debounce typing by 500 ms and allow one operation in flight. Each submitted snapshot receives a random operation ID that is reused on retry. Typing during a save creates a new pending draft; the old acknowledgment must not erase it. Do not emit changes generated by applying a remote update.

If a remote change arrives while the editor is clean, display it and preserve focus/selection where possible. If the editor has a dirty draft, retain the draft separately, pause autosave, and show a comparison choice: use latest shared content or explicitly submit the local draft. Choosing the draft creates a fresh operation based on the latest revision; it may overwrite shared text under LWW. Do not silently clear typed text or treat an old acknowledgment as confirmation that all current typing was saved.

## State and transport lifecycle

- Authentication context holds the short-lived opaque bearer token in memory. Reload requires sign-in in the core design; show this behavior clearly.
- One socket per authenticated application instance; attach listeners once and remove the same listeners during cleanup.
- Join the active room after connection and on every reconnection; leave it on navigation.
- Use `auth.token` for Socket.IO and `Authorization: Bearer` for HTTP.
- Use the Render origin from `VITE_API_BASE_URL` for HTTP and `VITE_SOCKET_URL` for Socket.IO.
- Buffer room events while installing the join snapshot. Ignore revisions less than or equal to the currently installed revision.
- Show `Connecting`, `Live`, `Saving`, `Saved`, `Reconnecting`, and `Save failed` as distinct text states. `Saved` requires a committed acknowledgment and no later dirty content.
- Run a state resync every 15 seconds while joined and after tab focus returns. Clean clients apply newer state; dirty clients enter the same comparison flow.

## Failure handling

Disconnect pauses submission and preserves the current draft in memory. Reconnect fetches fresh state before any retry. For an uncertain in-flight operation, query its result through `note:status`; if not committed, offer explicit retry of the preserved snapshot after showing current shared state. Do not allow Socket.IO's automatic buffering to replay stale editor changes blindly.

A `401` or `UNAUTHENTICATED` ends the session and socket. Preserve an unsaved draft in memory during a same-tab login and offer copy/export before navigation; never attach it to a different user's room automatically. A `403` ends room access and clears room data. For database errors, keep the draft and show retry with no saved claim.

## Accessibility and responsive layout

Use visible labels, keyboard-operable dialogs, focus return after closing history, and a polite live region for connection/save changes. Online users need names, not color-only dots. Make the editor dominant on desktop and stack controls on narrow screens. A history drawer must not trap focus after dismissal. Use readable contrast and a reduced-motion mode.

## Validation

Test two browser contexts, double mounting/listener cleanup, remote changes during typing, lost acknowledgments, reconnection, expired sessions, restore conflicts, keyboard-only use, and direct reload of `/rooms/:roomId`. See [testing](testing-and-validation.md).
